# Threat-source expansion verification — 2026-10-16

The owner requests as many useful sources as possible. There is no product target that stops expansion at a particular source count. New sources need a usable data path, provenance, suitable handling and observable failure states. Resource budgets protect the desktop from untrusted or unexpectedly large inputs; they must be revisited as storage scales, never used to silently truncate coverage.

## Integrated in the v0.1.22 candidate

Ten sources increase the catalog from 45 to 55. All ten were fetched over fixed HTTPS URLs with redirects refused, parsed with the production parser, combined in the production index and checked for source-attributed local lookup. Nothing from the PC was sent to an indicator endpoint; URLs within the datasets were never followed. These are indicator counts, not numbers of distinct threats or proof of detection effectiveness. Lists overlap, including with existing sources.

Threatview describes its community feeds as free and best effort. Block List Project's downloaded headers say MIT while the repository identifies Unlicense; the catalog records both instead of hiding the discrepancy. Phishing.Database and DigitalSide identify MIT. Data is downloaded by the local service, not bundled as a redistributed threat database. The DigitalSide archive is explicitly historical in its catalog name and description; download time must not be read as indicator age.

Two large domain feeds receive an explicit one-million-entry budget instead of the former universal 400,000-entry ceiling. Other sources retain their smaller budgets. Text parsing streams lines rather than duplicating every line into another collection. Over-budget or mostly malformed input fails visibly and keeps the last usable cache; no partial prefix is accepted as a full database. Hash/domain/IP text feeds enforce their declared type so a changed feed cannot turn a domain into a malware-file match. FTP support extracts a host only and never opens a connection.

Review also found that new network sources needed explicit evidence categories in the verdict engine, and that a signed generic malware-hash match was incorrectly described using LOLDrivers' legitimate-vulnerable-driver explanation. Both are covered by regression tests. Repeated listings do not receive an independence/confidence bonus. Matches remain read-only investigation findings.

## Further expansion

- Block List Project malware was fetched successfully: 50,910,539 bytes / 2,656,407 lines. Integrating it requires larger-scale storage/index measurement; do not load only a truncated prefix or discard the candidate simply to maintain a source-count cap. Current index retains parsed feeds and rebuilds an immutable dictionary, so memory peaks matter on smaller PCs.
- DigitalSide network lists are still stamped 2024-10-18. Keep these out of present-day IP/domain verdicts; archive hash matches remain useful because a file fingerprint does not change owner like an address can.
- C2-Tracker is archived and its current feed files were removed. Inversion DNSBL is suspended. These were researched, not represented as working feeds.
- Next useful work includes source-published timestamps and expiry, deduplicated coverage accounting, source dependency/provenance groups, a disk-backed index for multi-million-record sets, and licensed/authenticated feeds with explicit key and health states.
- MISP warning lists, MITRE ATT&CK, CISA recovery guidance, public ransomware research and existing provider-authentication changes are recorded in [the earlier research](RESEARCH_2026-10-14.md). No direct Tor crawling was performed or claimed.

Reproduction evidence stays local under ignored `artifacts/v022-feeds/`: `download-evidence.json`, `parse-evidence.json`, SHA-256 values, raw provider data and the production-parser probe. The ten-source index contains 1,406,636 distinct indicators. The last local probe built it in 353 ms and retained about 266 MB of managed memory (445 MB process private bytes) while also retaining parsed input. `artifacts/v022-feed-parse.log` records these measurements; they are not universal performance guarantees and exclude the rest of the service.
