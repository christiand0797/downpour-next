## Corrections discovered while researching

- `ThreatVerdictEngine` treated distinct feed IDs as independent evidence. Aggregators and tiers can repeat upstream indicators. The v0.1.22 candidate removes the listing-count confidence bonus, retains the actual listed sources and measured evidence, and states that independence is unestablished. This includes the former extra bonus for multiple exact-file listings. Regression tests cover overlapping reputation lists, repeated IDs, exact hash evidence and observed connections.
- [SSLBL C2 IP CSV](https://sslbl.abuse.ch/blacklist/sslipblacklist.csv) says it was deprecated on 2025-01-03 and returns no indicators. Do not reintroduce it simply to increase the feed count. The existing 45 source definitions remain unchanged in this milestone.

## Driver research applied to v0.1.22

[Win32_PnPEntity](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-pnpentity) exposes hardware and compatible identifier arrays. [DriverHardwareID](https://learn.microsoft.com/en-us/windows/win32/api/wuapi/nf-wuapi-iwindowsdriverupdate-get_driverhardwareid) can refer to either. Match exact identifier membership, not prefixes or display names; a match explains association, while Windows Update determines current applicability. The candidate retains bounded identifier sets and surfaces truncation.

[WUA search criteria](https://learn.microsoft.com/en-us/windows/win32/api/wuapi/nf-wuapi-iupdatesearcher-search) support update identity and revision, not an arbitrary DriverHardwareID query. Targeted installation needs a new typed identity/revision request, revalidation in the elevated helper, explicit affected-device scope, audit and failure tests. Current installation is honestly labeled a fresh, all-applicable-drivers batch.

[Asynchronous WUA guidance](https://learn.microsoft.com/en-us/windows/win32/wua_sdk/guidelines-for-asynchronous-wua-operations) is the next search reliability task: caller-owned timeout/abort, cleanup, one active job and stale-completion isolation. The current synchronous call can remain pending; the prior elapsed-time check after `Search` returned never bounded the call and has been removed. Result codes, partial failures and capped output are now explicit, but cancellable search is not claimed complete.

[CM_Reenumerate_DevNode](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_reenumerate_devnode) may configure/start/remove device nodes and needs privilege. A real hardware rescan belongs in its own fixed UAC-confirmed audited operation, separate from read-only Refresh. Successful re-enumeration does not prove a working driver was installed. The v29 audit found driver/BYOVD checks and baselines, not a universal driver downloader to port.
